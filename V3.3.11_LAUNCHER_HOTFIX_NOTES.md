# V3.3.11 OTA Launcher Hotfix

This hotfix changes only the V3.3.11 OTA publishing/preflight launcher. The App source, Expo dependency versions, runtimeVersion, Android package, and native binary contract are unchanged.

## Why this hotfix exists
On the user's Windows PC, `npx expo install --check` reported only:

- installed Expo: `57.0.20`
- expected Expo: `~57.0.21`

The previous launcher treated every non-zero Expo dependency check as fatal, so the OTA was correctly not published.

## New safety rule
The launcher now captures the Expo dependency-check output and continues only when **all** of the following are true:

1. The check reports exactly one `expected version:` mismatch.
2. That mismatch is the `expo` package itself.
3. Both installed and expected versions are within Expo SDK `57.0.x`.

This is treated as a patch-level warning only.

Any other mismatch (React Native, expo-updates, safe-area, notifications, widgets, etc.), multiple mismatches, or an unrecognized Expo check failure still stops the OTA.

## Validation gates still required before publish
- npm install
- Expo dependency check (with the narrow Expo-57 patch exception above)
- TypeScript `tsc --noEmit`
- Accounting contract test
- Engine runtime test
- V3.3.11 feature audit
- Android Expo export / Hermes-Metro bundle preflight

Only after all gates pass will EAS Update publish to Android `preview`, environment `preview`, runtime `3.2.0`.
