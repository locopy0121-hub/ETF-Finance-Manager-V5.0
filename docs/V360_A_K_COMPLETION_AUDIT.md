# V3.6.0 A–K Completion Audit

Audit date: 2026-09-12. Baseline: `9a3893f`. This audit distinguishes persisted schemas from code paths actually rendered by the V3 App shell.

| Item | Status | Runtime evidence | Remaining physical-device verification |
|---|---|---|---|
| A. Android system layer | 完整完成（程式碼） | `App.tsx` reapplies immersive navigation on foreground and wraps the entire shell in four-edge `SafeAreaView`; every active V3 page is inside that shell. Native overlays cap their content height. | Gesture/three-button navigation, cutouts and OEM window-inset behavior. |
| B. App-wide keyboard avoidance | 完整完成（程式碼） | Ledger, dividend and calculator active screens use `KeyboardAwareScrollView`; settings and editors use automatic keyboard insets; `UniversalEditor` uses `KeyboardSafeFooter`. Modal sheets retain bottom inset padding. | Gboard/OEM IME behavior, last-input visibility and rotation/large-font cases. |
| C. Flow layout | 完整完成 | `MasonryDeck` and `FieldMetricGrid` render through `FlowLayout`/`FlowItem`. Six quick widths are mapped to 12/9/8/6/4/3 spans, wrap by available width, and retain independent card height and persisted order. | Narrow/large Android screens and accessibility font scaling. |
| D. Universal Editor | 完整完成（程式碼） | The persisted registry is mounted at `V3ThemeProvider`; React UI opens it by long press. Registry nodes are exposed in Settings → Special → Universal Editor. Immutable IDs/data keys stay unchanged. The same `UniversalEditorNode` owns real Size, Data, Interaction and Advanced configurations, so cross-renderer editing uses one persisted schema instead of renderer-specific editor models. | Native surfaces cannot launch a React Native modal while the App is closed; registered nodes are edited from the Settings inventory and serialized to those renderers. |
| E. Global/P&L colors | 完整完成（程式碼） | Universal fixed/theme/P&L/auto sources apply to React text/surfaces and are serialized to Widget and overlay renderers. Widget root/title/P&L and overlay root/status/field/summary nodes resolve text, background and border colors dynamically from the same positive/negative/neutral palette. Existing profile persistence is preserved and missing nodes fall back to prior theme/profile values. | Launcher Widget APIs do not support every CSS-like paint operation; unsupported paints use the resolved fixed/P&L color while preserving the source model. |
| F. Effects Stack | 完整完成（程式碼，相容降級） | The ordered 16-effect stack remains the only model. `EffectSurface` implements gradient, inset border glow/shadow, shimmer and sweep with SVG/native-driver layers that compose in order. Widget maps gradient to its supported solid endpoint and glow/shadow/shimmer/sweep to border/highlight paint; overlay uses native `GradientDrawable` plus compatible border/highlight fallback. All parameters remain persisted even when a renderer degrades. | Android launcher Widget remote-view primitives cannot animate continuously or reproduce true inner blur; static endpoint/highlight degradation is intentional to avoid background CPU/GPU use. |
| G. Floating monitor | 完整完成（程式碼） | Twelve modes share `MONITOR_TEMPLATES`; title/status/breathing visibility/density/source are persisted. Native table uses fixed header, scrollable bounded body, fixed summary/footer, drag/resize, minimize/restore and close-window without stopping the service. | Overlay permission, OEM background service policy, close/reopen UX and all template sizes on device. |
| H. Watchlist | 完整完成 | `watchlistSymbols` is persisted independently and excluded from `engine.ts`. Home supports All/Watchlist/Held/Popular, star add/remove, a dedicated watchlist view and drag ordering. Quote subscriptions include holdings plus watchlist. Monitor candidates support holdings/watchlist/all without creating accounting records. | Relaunch persistence and live quote behavior under offline/OTA-upgrade conditions. |
| I. Settings coverage audit | 完整完成（程式碼） | `GENERATE_UI_INVENTORY.cjs` scans App, screens, charts, Widget, overlay and legacy TS/TSX/Kotlin sources and regenerates JSON/Markdown evidence. Architecture audit fails on an unclassified entry. | The inventory is lexical rather than screenshot/OCR based; runtime-only text returned by remote APIs is data, not a display-name literal. |
| J. Editor UX | 完整完成 | Nine collapsible sections, live preview, copy-style state, page/App type application and fixed Cancel/Reset/Save footer are implemented. Size controls width/ratio/dimensions/height/radius; Data controls binding/format/decimals/percentage/unit/sign/P&L source; Interaction controls press/long-press/double-tap/navigation/expand/drag/resize; Advanced controls visibility/state/refresh/readonly/system-fixed/capability flags. | K. Acceptance | 部分完成 | TypeScript, architecture audit, V3 native audit, finance/formula regressions, dividend cutoff and preflight run without modifying finance core. PR12 adds a deterministic device-acceptance harness and generated evidence at `docs/generated/V360_DEVICE_ACCEPTANCE.md`; current result is 19/19 static PASS with all 19 physical-device items explicitly pending. ## Financial-core guard

No change in this completion pass touches `src/v3/engine.ts`, `src/v3/formulaEngine.ts`, `src/domain/metrics.ts`, `src/domain/simulation.ts`, holding records, ledger records, dividend records, or their persisted formats. Watchlist-only symbols create zero-accounting display rows in the floating payload and never enter portfolio calculations.
